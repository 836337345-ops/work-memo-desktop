# V2.11 开机自启动任务卡

## 一、版本、分级与基线

- 版本：V2.11。
- 固定基线：`13b3b87b99df7d7e49aed6a7405edcdc7244aa2d`（V2.10 用户验收通过后的 `integration/v2`）。
- 任务分级：普通功能，涉及 Windows 登录启动项；执行可见开发任务、PM 审查与一次集成、固定提交上的独立 QA。
- 当前阶段：用户已确认，待开发任务完成启动验真后进入“开发中”。

## 二、用户确认的功能

1. 在左侧栏最下方、现有“导出事项”下方增加“开机自启动”开关。
2. 开关状态必须读取并反映 Windows 当前真实设置；未设置时默认关闭，不以浏览器存储伪造状态。
3. 用户开启后，登录 Windows 时正常显示程序主窗口；无需管理员权限，不静默启动或最小化。
4. 开启或关闭立即生效。操作期间开关不可重复点击；失败时保持操作前的状态，并在开关附近显示通俗错误提示。

## 三、技术与公共契约

- 使用 Tauri v2 官方 `tauri-plugin-autostart`，注册 Rust 插件、前端依赖，并只开放 `enable`、`disable`、`isEnabled` 所需权限。
- 前端初始化时调用 `isEnabled()`；切换时调用 `enable()` 或 `disable()`，成功后再次读取实际状态，不采用仅更新界面的假成功。
- `Sidebar` 内部组件契约允许新增：当前启用状态、读取/切换中状态、错误信息及切换回调；由 `App` 负责实际状态与失败处理。
- 不修改 `src/types.ts`、`src/api.ts`、`docs/CONTRACT.md`、数据库、备份或导出格式。
- 若官方插件与当前 Tauri 版本或单实例插件存在兼容问题，停止扩展并报告 PM，不自行改用注册表脚本、计划任务或第三方启动器。

## 四、允许修改范围

- `package.json`、`package-lock.json`。
- `src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/src/lib.rs`、`src-tauri/capabilities/default.json`。
- `src/App.tsx`、`src/App.test.tsx`。
- `src/components/workbench/Sidebar.tsx`、`sidebar.css`、`Sidebar.test.tsx`。
- 与官方自启动插件封装和上述测试直接相关的新前端文件。

## 五、禁止事项

- 不修改现有事项、分类、跟进、备份、导出和单实例业务行为。
- 不直接编写注册表、启动文件夹或计划任务脚本；不请求管理员权限。
- 不读取或改变正式用户数据；开发自测不得改变正式安装版的真实启动项。
- 不修改版本号、`main` 或安装包；不上传、发布或清理工作树。

## 六、验收条件

1. 左侧栏最底部显示“开机自启动”开关，位置、开启/关闭状态、禁用状态及错误提示清楚可辨，键盘与辅助功能可用。
2. 初始化成功反映真实状态；初始化失败显示错误且禁止误操作。
3. 开启成功、关闭成功、开启失败、关闭失败、连续点击保护均有自动化测试；失败不得错误翻转界面状态。
4. 执行完整 `npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml` 和差异格式检查。
5. 独立 QA 在固定集成提交上复核权限最小化、自动化和构建。若进行真实 Windows 启动项验证，只能使用独立调试标识，完整记录操作前后状态并恢复，不得触碰正式安装版启动项。

## 七、交付与停止条件

- 开发员使用独立工作树和 `codex/v211-autostart-toggle` 分支，先运行 `scripts/setup-codex-worktree.ps1` 并核对固定基线。
- 完成后提交并回报任务 ID、工作树、分支、提交号、修改范围、测试、构建、Windows 限制和未提交文件。
- 工作区必须干净；达到开发交付即停止，不得自行集成、创建安装包或开启 QA。

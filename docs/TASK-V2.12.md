# V2.12 日历筛选、事项操作、星标与跟进草稿任务卡

## 一、确认、基线与分级

- 用户于 2026年9月12日确认本任务全部需求。
- 固定业务基线：`e01e361e77995364a6f5c3e276d798d1d0ef0f51`（V2.11 已交付并合入 `main`）。
- 分级：数据安全功能。星标需要 SQLite 持久化及旧数据库、备份恢复兼容；执行可见 Terra Medium 开发、PM 一次集成和固定提交独立 QA。
- 本版本不打包、不修改 `main`，直至自动测试和用户调试验收完成，并再次取得明确打包授权。

## 二、最终需求与验收结果

1. 工作日历增加状态筛选：全部、进行中、已完成、已暂停；支持多选，默认全部，并与现有类别筛选叠加。
2. 新建事项的“保存并关闭”旁增加“取消”。空白新建直接关闭；已有输入时沿用未保存确认，确认放弃后关闭。
3. 事项卡“修改编辑”右侧增加“删除”；沿用现有二次确认和软删除到回收站，不增加永久删除。
4. 事项卡增加 `☆/★` 星标切换并持久保存。事项卡和日历事项的状态灯后显示已标记的 `★`。事项列表默认星标在前，同一星标组继续按现有截止日期正序、无日期最后及同日创建时间规则排序；日历仅在同一天内将星标置前，同组保持现有顺序。不新增星标筛选或设置。
5. 跟进项勾选后显示“已完成”，取消勾选后同步移除文字。
6. 验收反馈替换原手动保存规则：事项卡跟进清单取消“保存”按钮和未保存选择提示；在收起卡片、点击卡片外部、切换事项、删除事项或离开当前页面前，若有变更则自动保存一次。保存失败时不继续原动作，保留编辑内容并显示错误。
7. 事项卡未勾选清单行的输入框延伸到可用右边界；已完成项自动排到未完成项之后，两组内部均保持原顺序；“已完成”文字为红色加粗。
8. 事项卡最右侧增加“重要事项”切换按钮；选中后标题前显示现有星标。新建事项的标题行右侧增加“重要事项”复选框，选中后创建为星标事项。事项卡和日历现有星标样式及置顶规则不变。
9. 事项卡删除必须显示确认框，确认后才软删除；回收站还原后刷新原列表，不得误打开“新建事项”右侧栏。
10. 新建和修改事项保存时统一自动移除空白跟进项，不因空白项报保存失败；新建跟进项入口前显示“+”。
11. 恢复新建事项和修改编辑页面原有的“清单模板设置和应用”模块，行为与既有模板契约一致。

## 三、公共契约与数据安全

- `src/types.ts`：在 `ItemInput` / `WorkItem` 数据链路增加唯一布尔字段 `isStarred`；新建默认 `false`。
- `src/api.ts`：优先复用现有事项创建、更新和删除接口，不新增单用途星标命令。
- SQLite `items` 增加非空布尔兼容列，旧数据库升级默认未星标；迁移必须幂等，不删除、不重建用户事项。
- 新备份写入星标；旧备份缺少字段时默认 `false`；恢复失败保持原数据。既有 `todo` 历史清理兼容逻辑不得删除或改义。
- 跟进草稿只改变事项卡的提交时机；成功保存仍复用现有整项事务更新，失败不得丢失界面草稿或伪装成功。删除前若自动保存失败，不得继续删除。

## 四、允许修改范围

- 事项类型、现有事项 API 调用与筛选/排序工具。
- `App`、`WorkCalendar`、`ItemList`、事项编辑栏及已有确认弹窗相关组件和样式。
- Rust 事项模型、SQLite 初始化/迁移、事项读写、备份恢复及其测试。
- 与上述行为直接对应的 Vitest、Rust 和 Playwright 测试。
- 不新增第三方依赖，不处理 V2.12 之外的历史代码精简任务。

## 五、必须验证

- 定向组件测试覆盖自动保存的各种触发点和失败阻断、完成项置底与样式、新建/修改空白项清理、两处重要事项入口、删除确认、回收站还原及清单模板恢复。
- `npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml`、`git diff --check` 全部通过。
- 使用隔离虚构数据验证旧数据库迁移、旧/新备份恢复和星标持久化，不读取正式用户数据。
- Playwright 验证日历与事项卡关键路径；真实 Windows 界面仍由用户在固定集成提交的调试版验收。

## 六、停止条件

- 发现需要新增依赖、改变公共字段命名、扩大到星标筛选/批量操作、改变删除方式或无法保证旧数据安全时，停止并报告 PM。
- 开发员完成后提交全部允许范围，工作区必须干净，回报提交号、测试结果、迁移证据和遗留限制；不得自行合入 `integration/v2`、`main` 或创建 QA。

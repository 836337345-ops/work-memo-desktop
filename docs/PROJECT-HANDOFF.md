## 二、产品形态与技术基线

- Windows 本地中文桌面软件，日常功能离线运行，不需要账号。
- 桌面框架为 Tauri 2；界面为 React 19 + TypeScript + Vite；本地数据为 SQLite；Rust 负责本地数据接口。
- 默认窗口标题为“工作备忘录”，尺寸 1440×920，最小尺寸 1060×700。
- 调试版使用独立应用标识 `com.local.workmemo.dev`，标题为“工作备忘录 · V2 调试版”。
- 启用了单实例保护；再次启动时聚焦已有主窗口，避免两个实例同时写入同一数据库。
- 界面采用浅色、简洁、克制的 shadcn 风格设计令牌体系，保留浅绿色品牌主色；未引入 Tailwind、Radix 或 shadcn CLI。

## 三、主界面结构

界面由三部分组成：

1. 左侧导航：工作日历、快捷显示、状态/时间/分类筛选、回收站、备份恢复和导出入口。
2. 中间工作台：标题、事项数量、搜索、新建事项和事项卡列表。
3. 右侧编辑栏：平时隐藏；只有新建事项或点击事项卡“修改编辑”时打开。

当右侧编辑栏隐藏时，中间工作台使用更多横向空间。编辑栏内部只有一个滚动区域，顶部操作栏固定，不随内容滚动。

## 四、事项数据与状态

每条事项包含：

- 事项标题：必填。
- 事项情况：可选的多行内容。
- 所属类别：可选；未选择时为“未分类”。
- 截止日期：可选，只保存日期。
- 状态：进行中、已完成、已暂停。
- 最新进度及历史进度：每次提交形成独立记录，保留提交时间，最新记录排在最前。
- 跟进清单：每项包含文字和完成勾选状态。
- 备注：可选的多行内容。
- 创建时间、更新时间和回收站时间。

新建事项默认状态为“进行中”。系统不再提供“待开展”；打开旧数据库或恢复旧备份时，旧 `todo` 测试事项及其关联跟进、进度会被清除，其他事项不受影响。

跟进项完成与否不会自动改变事项状态。

## 五、分类

新数据库默认建立以下八类，并按该顺序显示：

1. 推广
2. 销售
3. 拓展
4. 包装
5. 礼品
6. 事务
7. 活动
8. 其他

用户可以新增分类、改名和上下调整顺序。分类名称不能为空或重复。删除分类前需要确认；分类删除后，关联事项保留并转入“未分类”，该分类的跟进模板同时删除。打开既有数据库不会用默认八类覆盖用户已经保存的分类。

## 六、新建与详情编辑

- 点击“新增事项”后打开右侧编辑栏。
- 从某个分类筛选下新建时，默认带入当前分类；从日历某日点击“新增计划”时，默认带入对应日期。
- 编辑栏可修改标题、类别、截止日期、事项情况、备注和跟进清单。
- 编辑栏不显示最新进度编辑和事项状态编辑；这两项在事项卡上处理。
- 顶部固定显示“保存并关闭”；已有事项同时显示“删除事项”，新建事项不显示删除。
- 点击“保存并关闭”成功后自动关闭编辑栏，不提供额外的普通关闭按钮。
- 标题为空时禁止保存。保存失败时保留当前输入并显示错误，可再次重试。
- 编辑内容未保存时，切换事项、筛选、日历、弹窗或关闭程序前会要求确认是否放弃。
- “删除事项”执行软删除并移入回收站，不会永久清除。

## 七、跟进清单与模板

- 编辑栏跟进区第一行左侧为“添加清单”，右侧为蓝色“模板设定/应用”，具体清单显示在其下方。
- 模板按事项类别独立保存；未选择类别时不显示模板入口。
- 每个模板可自定义名称和若干有序文字项，并可新建、编辑、删除或应用。
- 应用模板会把模板文字追加为未完成的跟进项；空项和与当前清单重复的文字不会重复添加。
- 删除模板不会删除已经写入事项的跟进项。
- 编辑栏和事项卡均可新增、修改、勾选和删除跟进项；事项卡正在由右侧详情编辑时，卡片内联编辑会暂时锁定。

## 八、事项卡最终展示与操作

事项卡默认收起，但始终显示：

- 最左侧展开/收起按钮。
- 与状态对应的呼吸灯圆点。
- 事项标题。
- 类别和日期小字，日期统一显示为“X年X月X日”；无日期显示“未设日期”。
- 状态选择框。
- 最右侧“修改编辑”按钮。
- 最新进度标题和完整内容，不截断、不省略。

状态灯颜色为：进行中绿色、已暂停红色、已完成橙色。

点击最新进度标题或内容后才显示进度输入框。提交成功后输入框自动隐藏，但事项卡原来的展开状态不改变；提交失败时恢复输入文字并显示错误。

展开事项卡后显示独立底框的事项情况、跟进清单和备注：

- 事项情况和备注只展示，不在卡片上编辑。
- 跟进清单标题同行提供“添加跟进”，清单可直接编辑、勾选或删除。
- 状态可直接通过标题行的状态选择框修改。
- 不提供“一键完成”按钮。
- 点击“修改编辑”才打开右侧详情编辑栏。

从日历跳转到事项时，工作台会滚动到目标事项、醒目标记并展开该卡片，但不会自动打开右侧编辑栏。

## 九、筛选、搜索与排序

- 程序启动默认只显示“进行中”事项，时间为全部，分类为全部。
- 左侧独立快捷按钮顺序为：工作日历、显示全部、显示进行中工作。
- “显示全部”会清除搜索并恢复全部状态、全部时间和全部分类。
- “显示进行中工作”会清除搜索，只保留进行中状态，时间和分类恢复全部。
- 状态、时间、分类三个维度可以同时组合筛选，不是互斥的单维筛选。
- 左侧分组顺序为状态、时间、分类。默认展开状态，默认收起时间和分类；每组可独立展开/收起，展开状态保存在本机界面设置中。
- 分组收起时显示当前条件摘要，例如“时间 · 全部时间”，不使用大段空白分隔。
- 状态选项：全部状态、进行中、已完成、已暂停。
- 时间选项：全部时间、今天、本周、下周、本月、下月、历史。
- “历史”指截止日期早于本机今天的事项，不限制事项状态。
- “逾期”不是左侧可选筛选项；进行中事项的截止日期早于本机今天时，在卡片标题旁标记“逾期”。
- 分类选项包含全部分类、未分类及所有自定义分类。
- 搜索覆盖标题、事项情况、最新进度、跟进文字和备注，并可与三个筛选维度叠加。
- 默认按截止日期从近到远排序；无日期事项最后；同日期按创建时间从新到旧。
- 本周从周一开始，所有日期范围包含起止当天。

## 十、工作日历

- 左侧“工作日历”是独立入口，打开后默认显示当前月，并固定展示六周网格。
- 支持上月、回到今天、下月和关闭日历。
- 日历使用全部未删除且设置了截止日期的事项，不继承工作台当前状态、时间、分类或搜索条件。
- 日历顶部可按一个或多个分类筛选，包含“未分类”；点击“全部”清除日历分类限制。
- 日期格最多直接显示三条事项标题，每条标题前都有其自身状态对应的呼吸灯；超过三条时显示“另有 N 项”。
- 鼠标悬停或键盘聚焦日期时显示当日全部事项列表。
- 点击浮窗中的事项会返回工作台并定位、标记、展开对应事项卡。
- 浮窗中的“新增计划”会打开新建事项编辑栏，并预填该日期。
- 周六、周日和已标注节假日的日期数字显示红色。
- 当前内置节日标注包括元旦、春节、清明、劳动节、母亲节、端午、中秋和国庆。

## 十一、回收站

- 删除事项后进入回收站，不提供永久清空功能。
- 回收站事项只读，事项卡提供“还原”。
- 还原后事项恢复到正常列表，并可继续编辑。
- 回收站搜索仍可使用，但不套用正常列表的状态、时间和分类筛选。

## 十二、备份与恢复

备份内容包括分类、全部事项、回收站事项、进度历史、跟进清单和跟进模板。

备份提供两种方式：

1. “一键备份到本地”：直接在应用数据目录下的“备份”文件夹生成 JSON。文件名为 `工作备份文件YYYYMMDD.json`；同日重复备份自动使用 `-2`、`-3` 等后缀，不覆盖已有文件。
2. “选择位置并导出备份”：由用户选择 JSON 保存位置。

恢复流程：

- 先选择 JSON 文件并完整校验版本、时间、分类、事项、模板和关联关系。
- 校验通过后提示恢复会替换当前数据。
- 用户确认后，先自动保存当前数据的安全备份，再通过数据库事务替换。
- 校验或恢复失败时保留原数据；成功后显示恢复数量和安全备份路径。

## 十三、TXT 事项导出

- 导出状态、时间和分类三个维度均支持多选，并各自提供“全选”和“反选”。
- 状态选项为进行中、已完成、已暂停。
- 时间选项为今天、本周、下周、本月、下月、历史；面板不显示“全部时间”和“已逾期”。
- 分类选项包含全部现有分类和未分类。
- 每个维度至少选择一项；全选在数据接口中表示该维度不限范围。
- 导出只包含未删除事项。
- 文件名默认建议为 `工作事项汇总YYYYMMDD.txt`，编码为 UTF-8。
- 输出按当前分类顺序分组，未分类最后；每组按截止日期正序，无日期最后。
- 一级标题格式为中文序号加类别，例如“一、活动”。
- 事项格式为“序号、X年X月X日，事项标题，最新进度；”，组内最后一项使用句号。
- 无日期写“未设日期”，无进度写“暂无最新进度”。

## 十四、本地数据与安全边界

- 正常数据保存在 Windows 当前用户的应用数据目录，数据库文件名为 `work-memo.sqlite3`，不写入源码目录或安装目录。
- 测试和调试可通过 `WORK_MEMO_DATA_DIR` 指向独立数据目录。
- 前端只通过本地 Tauri 接口访问数据，没有远程服务。
- 分类、模板、事项、跟进和进度写入 SQLite；时间戳使用 RFC3339，截止日期使用 `YYYY-MM-DD`。
- 保存、进度提交、备份和恢复失败时向用户显示中文错误，不把失败操作伪装为成功。
